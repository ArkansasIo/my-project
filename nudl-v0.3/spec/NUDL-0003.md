# NUDL-0003: Expression Core (Draft)

**Status:** Experimental, version 0.3.0  
**Language:** Nudl Data Format (NUDL)

## 1. Purpose

This draft defines the first arithmetic expression semantics intended for the NUDL language. The implementation in this milestone is a standalone expression evaluator; it does not claim to parse the entire NUDL file format.

## 2. Numeric model

The current prototype evaluates expressions as IEEE-754 double-precision values. Integers are accepted as numeric literals but are represented as doubles internally. Exact decimal and arbitrary-precision numeric types are future work.

## 3. Operators and precedence

From highest to lowest:

1. Parenthesized expressions and numeric literals.
2. Unary plus and minus.
3. Multiplication and division.
4. Addition and subtraction.

Binary operators associate left-to-right. Division by zero is a runtime evaluation error. Non-finite results are rejected.

## 4. Lexical rules

Whitespace is ignored. A numeric literal consists of decimal digits with an optional fractional part and optional exponent. The prototype accepts forms such as `12`, `12.5`, `.5`, `1e3`, and `2.5E-2`.

## 5. Diagnostics

Malformed expressions, missing closing parentheses, unexpected trailing tokens, invalid numeric literals, division by zero, and non-finite arithmetic results must produce an error rather than silently returning a value.

## 6. Compatibility and scope

The expression module is a component of NUDL, not a converter or wrapper for another data language. This draft does not define variables, functions, booleans, strings, records, dataset queries, imports, or execution of complete `.nudl` source files. Those features require subsequent normative drafts and tests.
